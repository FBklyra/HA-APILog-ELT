# ADR-013 — Out-of-row completion in the data path

- **Status:** Accepted
- **Date:** 2026-11-05
- **Author:** Freddy Beltran

## Context
Logs omit out-of-row values by design (Db2 LOB / long VARCHAR / DECFLOAT / XML stored out of row, Postgres TOAST,
MySQL minimal row images, SQL Server update masks, Oracle LOB operations): 12 % of the row changes of the ERP
test schema. They were routed through the integrity machine (SUSPECT → critical incident → table hold → keyed re-read
→ replay → attach), which at production scale never converged (root-cause analysis of the Db2 to warehouse initial-load failure, cause RC1).

## Decision
- A `needs_keyed_reread` signal **with keys** is completion work, not an integrity event. The partial image is applied
  at once (the loader and the destinations keep the values of absent columns); the missing columns are fetched by key
  in batches and written through the main stream (`alelt_hub.completion`, table `table_completion`).
- Entries are queued when the signal's transaction commits (commit position); one entry per (table, key), folded.
  Fetches: `VERIFY_TABLE{rows, columns}` through the agent (<= 1000 keys and 48 KiB of arguments per command, <= 4 in
  flight) or `SourceConnector.keyed_reread` for remote sources (control lane). Only the signalled columns are
  written, placed in the buffer at their read position R; an entry is done when a read at `R >= last_pos` was flushed.
- Convergence: a column written by a completion changes only through a signal; any change after R signals again and
  re-queues the key, so the last write is always the fetch issued after the newest signal. A DELETE committed after
  the newest signal cancels the entry (no resurrection).
- Completion floor: main-stream flushes carry `<cid>#t:<table>` = min(first_pos) of the table's open entries
  (ADR-005 amendment); `alelt completion rebuild <cid>` recreates the entries from the spool after a metadata loss;
  retention keeps the spool from min(first_seq).
- Integrity keeps every unexplained record and the other signal classes; a table whose completion cannot converge
  (no key, no fetch capability, more than `ALELT_COMPLETION_PENDING_MAX` entries) goes to integrity → resync.
  Incidents only for `COMPLETION_STALLED` (no answer for `ALELT_COMPLETION_STALL_S`) and `COMPLETION_OVERSIZE`.

## Consequences
- No table hold, no incident for the normal case; certification, switch and settled verification wait while entries
  are pending (soft gate).
- Engine-agnostic: a source only decides what to signal (keys + columns).
- Residual risk: a source that changes an out-of-row column without logging a row image (not the case for Db2 DATA
  CAPTURE CHANGES).
