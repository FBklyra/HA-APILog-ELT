# ADR-012 — Table lifecycle and gate precedence

- **Status:** Accepted
- **Date:** 2026-11-05
- **Author:** Freddy Beltran

## Context
Initial load was an opt-in of wizard pipelines; file-configured connections started from `current` with empty
tables, and the catalog harness replayed history through the log instead. Four hold kinds (snapshot, schedule,
integrity, schema) had no written precedence, and schedules held every table from the first batch, so a schedule
could stop an initial load from ever landing (root-cause analysis of the Db2 to warehouse initial-load failure, causes RC2 / RC3).

## Decision
- One row per enabled table (`table_lifecycle`, owner `alelt_hub.lifecycle`): `NEW → INITIAL_LOAD → CATCH_UP →
  STREAMING`, plus `RESYNC` and `DISABLED`. Only `lifecycle.move()` writes the phase. Holds (`table_hold`) remain the
  gate mechanism; the lifecycle row is the phase.
- **Initial load is the default for every entry point** (file seed, wizard, config import / revision, console, API,
  catalog ingest of edge and remote connections, a new table under `allow_new_tables`). `initial_load: none` (tables
  start empty, STREAMING at once) and `replay_from: <pos>` (test / ops) are explicit modes. Connections that flushed
  before this release are migrated as `STREAMING, mode=legacy` (no retroactive snapshot).
- Gate precedence: integrity hold > schema hold > initial load / catch-up / resync (they **ignore the schedule window
  and deferral**: a schedule is a latency class for changes; only the snapshot's source read waits for
  `snapshot_window`) > schedule gate (placed at the `CATCH_UP → STREAMING` transition, under the pipeline lock, at the
  attach position) > completion (soft gate: certification, switch, settled verification).
- The handoff positions: hold placed at the flushed position `S0`, agent read position `R_a` in the chunk header,
  catch-up from `max(S0, R_a)` (bulk pass to `U1`, then the attach tail `(U1, P]` under the lock). Snapshots are
  resumable by `key_from` with the same snapshot id.
- `verified_at` (post-snapshot reconciliation MATCH) is required by certification; a settled MISMATCH starts a resync
  (bounded).

## Consequences
- Every connection on every engine lands the rows that existed before capture; schedules never block an initial load.
- The driver (`lifecycle.drive`, control lane) is idempotent and restartable from metadata only.
- Harnesses assert one written rule per schedule class (DESIGN.md §8.1, `tests/ladder/README.md`).
