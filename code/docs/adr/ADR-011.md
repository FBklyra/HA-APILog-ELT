# ADR-011 — Engine-agnostic SPIs and canonical model

- **Status:** Accepted — refreshed 2026-11-04 (engines implemented, completeness contract)
- **Date:** 2026-11-03
- **Author:** Freddy Beltran

## Context
Many sources and destinations are expected. Engine logic in the core would make each new engine a rewrite.

## Decision
- Core modules (hub, txn, loader, schema, verify, console) know only the canonical model in `hub/alelt_common/models.py` (Position, CanonicalType, ChangeEvent, ChangeSet, CatalogSnapshot, BatchHeader, Command).
- Engines implement the Source SPI (`connectors/sources/_spi`, contract `REMOTE.md`) and the Destination SPI (`connectors/destinations/_spi`, kit + conformance suite `alelt_dst_kit`); edge engines implement the C plugin vtable `alelt_source_vtbl`.
- Every source classifies every record it reads (`alelt_common/completeness.py`: decoded / ignored / needs_keyed_reread / needs_catalog_refresh / unsupported) and keeps a census; signals travel as ordinary events.
- Implemented today: sources Db2 (edge), PostgreSQL, MySQL, MariaDB, Oracle, SQL Server (remote); destinations PostgreSQL, generic SQL (several dialects), Snowflake, Iceberg, Delta, ClickHouse, Kafka API, BigQuery, Redshift, Fabric, Databricks (maturity per connector README).

## Consequences
- Positions are opaque to the core (source-provided comparator).
- Conformance suites gate every plugin; a destination not yet on the kit base is ported to it (one implementation style).
- Adding an engine is plugin work only.
