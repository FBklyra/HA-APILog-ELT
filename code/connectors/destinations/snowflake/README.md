# Snowflake destination (`alelt_dst_snowflake`)

Implements `alelt_common.spi.DestinationConnector` (DESIGN.md §6). All SQL is generated by pure functions in
`sqlgen.py`; the only I/O seam is `Executor` (tests use a recording fake, no Snowflake needed).

| Module | Role |
|---|---|
| `migrations/NNN_*.sql` | Idempotent templates (`{{DATABASE}}`, `{{LANDING_SCHEMA}}`, `{{VIEW_SCHEMA}}`, `{{LEGACY_SCHEMA}}`, `{{WAREHOUSE}}`, `{{CREDIT_QUOTA}}`, ...): roles, `ALELT_WH` (auto-suspend 60 s + resource monitor), schemas, `ALELT_CONTROL` tables, `ALELT_STAGE` stages, `SWITCH_SOURCE` / `SWITCH_WAVE` |
| `migrations.py` | Runner: `ALELT_CONTROL.MIGRATION_HISTORY` (version, checksum of template); edited applied migration => error |
| `destination.py` | `SnowflakeDestination`: bootstrap, ensure_table (golden DDL or type map), add_column, read_checkpoint, apply, load_snapshot, quarantine, archive_raw / purge_raw_archive, verify helpers, publish_view |
| `rows.py` | Final operation per key within a batch; TRUNCATE; PK updates; keyless surrogate id |
| `parquet.py` | pyarrow + zstd load files |
| `profile.py` | Output profile (system-column names) from `config/output_profiles.yaml` |
| `types.py` | Canonical -> Snowflake fallback map |
| `executor.py` | Key-pair auth from env (`ALELT_SNOWFLAKE_ACCOUNT/USER/ROLE/WAREHOUSE/DATABASE`, `ALELT_SNOWFLAKE_PRIVATE_KEY_PATH` or `ALELT_SNOWFLAKE_PRIVATE_KEY`, `..._PASSPHRASE`) — no secrets in config (R9) |

## apply (R6, F-05)
1. Read the checkpoint (= the base the batch is planned from, or `expected=`); `checkpoint >= to_pos` => no-op.
2. Per table and per image column set (partial images update only their columns, never NULL the others): Parquet -> `PUT @ALELT_STAGE.PARQUET/<stream>/<batch>/` -> `CREATE OR REPLACE TRANSIENT TABLE TMP_<table>_<unique hash> ... LIKE landing` -> `COPY INTO` (before the transaction: DDL auto-commits in Snowflake).
3. `BEGIN` -> **conditional `MERGE ALELT_CONTROL.CHECKPOINT`** (matches only the position/batch the batch was planned from; takes the control-table lock; result must be 1 row, else `ROLLBACK` + `CheckpointConflictError`, or no-op if the same batch won) -> soft-delete on TRUNCATE -> `MERGE` per table/group -> `INSERT AUDIT_BATCH` -> `COMMIT` (`ROLLBACK` on error). Per-table watermarks (JSON, `WATERMARKS` column, migration 006) are written by the same checkpoint MERGE.
4. Drop transient tables, remove staged files (also on failure; a retry recreates them).

`ensure_table` adds columns missing from an existing landing table (additive drift). **Status (X-126): verified with mock executors and SQL generation only — exactly-once is NOT claimed for Snowflake until a real-account run passes.**

## Switch
`CALL ALELT_CONTROL.SWITCH_SOURCE('<TABLE>', 'ALELT')` (requires a valid row in `ALELT_CONTROL.CERTIFICATION`) or `'LEGACY'`
(rollback to the existing landing schema of the legacy pipeline). Views use the explicit list in `ALELT_CONTROL.VIEW_COLUMNS`
written by `publish_view`. `SWITCH_WAVE(wave_id[, source])` checks certification of the whole wave first.
The legacy schema SELECT grant for the procedure owner is an account-admin prerequisite (R2), not a migration.
One ALELT database per source connection (procedures are rendered per landing schema).
