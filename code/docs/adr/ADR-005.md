# ADR-005 — Exactly-once via checkpoint in the same transaction

- **Status:** Accepted — amended 2026-11-04 (checkpoint compare-and-set, per-table watermarks; design review F-05 / F-06)
- **Date:** 2026-11-03
- **Author:** Freddy Beltran

## Context
At-least-once with idempotent merge hides duplicates and gaps; certification needs provable delivery (R6). The first version relied on a single writer per stream (a hub lock) and gave each replay stream its own checkpoint row with no rule for which position wins on restart.

## Decision
- The destination applies a batch and writes the stream checkpoint plus the audit row in **one** transaction. Destinations that cannot do this are rejected by the Destination SPI.
- The checkpoint is **compare-and-set inside that transaction**: the value found must equal the value the applier expected (default: read at the start of `apply`), else `CheckpointConflict` and nothing commits. `apply` is a no-op when the checkpoint is already at or beyond `to_pos`. The destination, not a hub lock, arbitrates between concurrent appliers.
- Checkpoint model: one **stream** checkpoint `<cid>` per connection + one **watermark** row `<cid>#t:<table>` per held table, written in the same transaction. Per table, the applied position is its watermark while held, else the stream checkpoint. Replay passes use their own pass checkpoint so an interrupted pass resumes exactly-once; on completion they advance the table watermarks, never the stream checkpoint.
- The hub mirror (`checkpoint_mirror`) is a cache, updated after the destination commit; on any disagreement the destination wins.

## Consequences
- Restart/replay resumes from the destination checkpoint; hub DR needs only code + destination state + the spool from `restart_seq`.
- Every destination ships a conformance test with two concurrent appliers; replay ×3 must be idempotent at the destination level, not only through the loader's skip.
- Exactly-once is claimed per destination only with evidence (DESIGN.md §5.3); no claim for a destination verified against mocks only.
## Amendment — stream + per-table watermark model in the hub (F-06, F-08, F-01; 2026-11-04)

| Term | Definition (code) |
|---|---|
| Stream checkpoint `P` | Destination checkpoint of `<cid>`: every change ≤ `P` of every table **not held** is applied. Mirror: `checkpoint_mirror.position/last_seq`; `restart_seq` = first batch of the oldest transaction open at `P`. |
| Table watermark `W_t` | Position through which table `t` is applied. Attached table: `W_t = P`. Held table: `W_t` = `start_pos` of its `table_hold` rows (one value for all held rows of the table, moved together by `alelt_hub.replay.advance_watermark`), with the scan start `restart_seq` recorded next to it. Destination side: the SPI watermarks of each stream row; `W_t = max` over streams. |
| Hold | `table_hold` row (`snapshot`, `schedule`, `integrity`); the main stream skips a held table **at flush time**, so a hold placed at any moment starts at the last *flushed* `P` — exact even with a non-empty loader buffer. Holds are effective from the first batch (schedule `ensure()` before every chunk). |
| Replay pass | One pass over the spool for many tables (`alelt_hub.replay.run`), each from its own `W_t`, into a transient stream `<cid>#pass:<id>`; the pass range `(W_t, U]` is persisted before anything is applied, the pass stream checkpoint makes a resumed pass exactly-once (change sets ≤ it are skipped). Decoded events come from the per-batch cache (decode once per batch × catalog version × decoder fingerprint). |
| Attach | Rejoining the main stream: bulk pass to `U1` without the pipeline lock, then the tail `(U1, P]` under the pipeline lock (main stream idle), then the hold is released; the next main flush includes the table. |

Rules
- `P` never waits for a held table; a held table never passes its integrity hold point (an `integrity` hold freezes `W_t`: schedule rounds, catch-ups and reprocess do not replay it; only its recovery does).
- Restart: the main stream resumes from `restart_seq`, skipping commits ≤ `P`; held tables keep `W_t` from metadata; a bulk pass with a persisted range is re-run (`replay.resume_passes`) and skips what its stream already committed; an attach tail is re-run under the lock.
- DR (hub metadata lost): rebuild the main stream from `<cid>`; for each table whose watermark (max over stream rows) is below `P`, recreate a hold at that watermark and replay it (scan from the lookback, the recorded `restart_seq` is gone).
- Snapshots: a snapshot sets `W_t` = snapshot start; its catch-up is a pass from there; an integrity hold during a snapshot takes over (`watermark_for_new_hold` = min of every hold and an unfinished catch-up).
- Integrity (F-01): the first unexplained quarantined record of a table holds it at `P` (≤ the record before); recovery = re-decode with the newest catalog (strict: nothing applied if any record of the table is still quarantined) → keyed re-read hook → resync; certification and switch are refused while not `IN_SYNC`.
- Transient pass checkpoint rows are deleted by destinations that implement `delete_checkpoint(stream)` after the hub recorded the pass.

## Amendment — completion floor, empty flushes, no per-cycle streams (ADR-012 / ADR-013; 2026-11-05)

- **Completion floor.** For a table with pending out-of-row completions, main-stream flushes carry the explicit
  watermark `<cid>#t:<table>` = min(first_pos) of its open entries. Meaning: `W_t < P` on a non-held table means
  "applied through `P` except out-of-row values signalled in `(W_t, P]`". When the entries drain, the key moves to
  the flush position (watermarks only move forward). DR: re-scan the spool `(W_t, P]` for signals
  (`alelt completion rebuild <cid>`); retention keeps the spool from min(first_seq) of pending entries.
- The main-stream invariant stays: every change `<= P` of every non-held table is applied — a partial image is applied;
  for keys in `table_completion` the destination may lack the listed out-of-row columns until a fetch read at
  `R >= last_pos` is applied.
- **Empty flush.** A flush with nothing to apply (only held / disabled / NEW tables in the range) opens no destination
  transaction; the mirror advances (`position`, `last_seq`, `restart_seq`) and `checkpoint_mirror.dest_position`
  records what the destination holds. A checkpoint-only transaction catches the destination up at most every
  `ALELT_CHECKPOINT_IDLE_S` (default = flush cadence, min 60 s) and at worker shutdown. Safe: the skipped range only holds
  changes of tables that are replayed from the spool by seq, never from `P`.
- **No per-cycle transient streams for completion.** Completion rows ride the main-stream flush. When the main stream
  has nothing to flush (idle source), they are applied through `<cid>#completion:<id>` whose checkpoint row is dropped
  right after use (listed per connection so a crash can retry the drop). Catch-up and attach pass streams are dropped
  after use too.
