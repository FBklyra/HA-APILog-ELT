# ADR-001 — Log-based capture via `db2ReadLog`

- **Status:** Accepted
- **Date:** 2026-11-03
- **Author:** Freddy Beltran

## Context
The source ERP workload (Db2 LUW 11.5.9, Windows) must be replicated without load or writes on the source (R1). Options: IBM Q/SQL Replication (ASN), triggers, query polling, log reading.

## Decision
Capture from the Db2 recovery log with the public IBM `db2ReadLog` API (filter ON: propagatable records of `DATA CAPTURE CHANGES` tables + commit/abort). No ASN, no triggers, no polling.

## Consequences
- Zero DDL/DML on the ERP source; only `DATA CAPTURE CHANGES` (DBA-owned) is required (OQ-02).
- Requires archive logging and DBADM/SYSADM for the capture user (V9).
- ALELT decodes log record layouts (V3–V7) → golden corpus + fuzzing (L3, L5).
- Lag must stay inside DBA archive retention (R3) → alert.
