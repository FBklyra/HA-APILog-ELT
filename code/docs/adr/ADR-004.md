# ADR-004 — Destination contract from the golden spec of the existing landing schema (configurable output profile)

- **Status:** Accepted
- **Date:** 2026-11-03
- **Author:** Freddy Beltran

## Context
dbt models and other consumers read the landing schema produced by the legacy pipeline today; switching must require no consumer change.

## Decision
- Names, types and semantics come from the golden spec in `config/golden/` (R8), exported from the existing landing schema — never from assumption.
- System column names come from a per-connection **output profile**:

| Profile | Synced / deleted columns | Use |
|---|---|---|
| `alelt` (default) | `_ALELT_SYNCED` / `_ALELT_DELETED` | New connections without an existing landing schema |
| `golden_spec` | Taken from the golden spec | Replacing a legacy pipeline; output identical to the existing landing schema |

- Vendor-specific profiles live in private extensions, not in the public core.
- History-mode, keyless surrogate and hashed columns follow the golden DDL; hash reproduction tracked by OQ-03.

## Consequences
- The ERP connection uses `golden_spec`; contract tests (L4) compare against golden DDL.
- Loader and destination plugins must not hard-code system column names.
